  curl -s localhost:4000/api/health | grep -o '"inspiration":{[^}]*}'
  curl -s "localhost:4000/api/inspiration?refresh=1" | head -c 200

   "behance":{"configured":false,"ok":false,"count":0,"stale":false,"cachedAt":null,
   "reason":"not configured: set BEHANCE_API_KEY (Adobe is not issuing new ones, see behance.js)"}}}

  That is what no-key looks like, and it is deliberately not an error.


WHAT IT WILL NOT DO
-------------------
  * It never puts the key in the browser, a log line or an error message. The key
    goes in a query string, so every message that could carry a URL passes through
    redactKeys() — there is a test named for exactly that.
  * A dead, slow, rate-limited or refusing Behance cannot empty or hang the
    dashboard: the last good cards stay, marked stale, and the failure is cached
    for the same 15 minutes so a dead host costs one request, not one per reload.
    (Not-configured is NOT marked stale, because a "Try again" button would be a
    lie — there is nothing to retry.)
  * Nothing from Behance is downloaded, re-hosted, or copied into a project. Each
    card is a link out with the designer named and their profile linked, and the
    strip says plainly that the work is theirs. Their CDN may still refuse a
    hot-linked cover — then the card shows a colour block, not a broken image.
  * api.behance.net sends no CORS headers, so the frontend never calls it
    directly; it only ever calls /api/inspiration. There is nothing to configure
    on Vercel for this.


WHY IT IS SHAPED THIS WAY (measured, 5 Sept 2026)
-------------------------------------------------
  GET api.behance.net/v2/projects, no key      -> 403 "A client or user is required"
  GET /v2/search/projects?q=…                  -> 404 (search removed from the API)
  response headers                             -> no access-control-allow-origin
  feeds.behance.net, Adobe's oEmbed host       -> no DNS at all
  www.behance.net/gallery/… from a server      -> 403, 453 bytes (nothing to scrape)
  new API keys                                 -> not issued any more; behance.net/dev
                                                  is closed and the Adobe Developer
                                                  Console has no Behance API
So the useful half of this feature is the local half, and the outside half is a
bonus for whoever already holds a key.
